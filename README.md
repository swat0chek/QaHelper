# qaHelp

qaHelp — рабочий помощник тестировщика. Не помни всё. Знай, где быстро найти.

24 раздела на русском языке, поиск по всей базе и адаптивный дизайн с сине-сиреневым свечением и пастельными карточками.

## Возможности

- Все карточки открывают отдельные страницы с материалами, примерами и оглавлением.
- Поиск по названиям, объяснениям, таблицам и коду; несколько слов, независимость от регистра и `е/ё`.
- Результаты ведут к конкретной теме. Запрос хранится в `?q=`: работает обновление страницы и возврат из материала.
- Копирование примеров, таблицы, локальные SVG-схемы и ссылки на документацию.
- На широком экране оглавление сбоку, на телефоне — перед текстом; длинные таблицы и код прокручиваются внутри своих блоков.
- Все материалы доступны локально без интернета. Внешние ссылки нужны только для дополнительного чтения.

## Запуск

Нужен **JDK 17+**. Для работы приложения Maven, Gradle, Node.js и внешние библиотеки не требуются.

Из корня проекта:

```shell
java --source 17 src/Main.java
```

Откройте **http://localhost:8080**. Остановка — `Ctrl+C`.

Другой порт:

```shell
java --source 17 src/Main.java 8081
```

В IntelliJ IDEA выберите JDK 17+ как Project SDK и запустите `Main.main()`. Рабочая директория — корень проекта (`$PROJECT_DIR$`). Порт можно передать через Program arguments. После изменения Java-маршрутов сервер необходимо перезапустить; изменения веб-файлов видны после обновления страницы.

Сервер слушает `127.0.0.1`. Это локальный справочник без БД, авторизации и редактора материалов. Для чтения и поиска нужен JavaScript. Не открывайте HTML напрямую через `file://`.

## Добавление материалов

Для существующего модуля редактируйте его файл в `web/modules/`. Тема имеет стабильный `id` (используется в ссылках), `title` и массив `blocks`. Поддерживаются:

- `paragraph`, `note`: поле `text`;
- `list`: массив строк `items`;
- `table`: `headers` и двумерный массив `rows`;
- `code`: `language` и `text`;
- `diagram`: три подписи `labels` и текстовое пояснение `text`;
- `links`: массив пар `[название, внутренний адрес]`.

Пример файла `web/modules/example.js`:

```javascript
window.qaModules['example'] = {
  topics: [{
    id: 'basics',
    title: 'Основы',
    blocks: [{type: 'paragraph', text: 'Объяснение с примером.'}]
  }],
  sources: [['Официальная документация', 'https://example.com/docs']]
};
```

Для нового раздела также добавьте объект в `sections` файла `web/data.js`:

```javascript
{
  id: 'example', title: 'Новый раздел', description: 'Описание материала.',
  icon: 'book', color: 'purple', href: '/example', file: '/modules/example.js'
}
```

Добавьте `example` в `MODULES` файла `src/Main.java` и перезапустите сервер. Обновите README и проверку ожидаемого количества в тестах; число разделов на главной вычисляется из каталога. Карточка и поиск используют общий каталог. Цвета: purple, blue, green, orange; иконки: http, laptop, api, database, book, bolt, gear, heart или короткий текст.

Текст рендерится через DOM/textContent, поэтому HTML-примеры не выполняются. Для HTTP-кодов добавляйте строки в `httpGroups` и обновляйте ожидаемое количество в тестах. Заголовки и примеры индексируются автоматически; поисковые данные не отправляются внешним сервисам. При ошибке загрузки поиск показывает сообщение, а не молча пропускает раздел.

## Проверка

Автотесты требуют **Node.js 22.13+** (только для разработки; используется встроенный SQLite) и запущенный сервер. По умолчанию тестовый адрес — `http://127.0.0.1:8081`:

```shell
java --source 17 src/Main.java 8081
# В другом терминале:
node --test tests/knowledge.test.cjs tests/toolbox.test.cjs tests/data-generator.test.cjs tests/boundary-generator.test.cjs tests/http-finder.test.cjs tests/bug-report.test.cjs tests/test-case.test.cjs tests/test-design-advisor.test.cjs
node tests/browser.cjs
```

Браузерная проверка требует установленный Chrome или Chromium. На Windows стандартные пути определяются автоматически; для другого расположения задайте `QA_CHROME`. Можно задать `QA_BASE_URL` для другого адреса сервера. Скрипт запускает свой headless-браузер, закрывает его по завершении и сохраняет снимки в игнорируемую папку `out/`.

Проверяются: целостность 24 разделов, 26 HTTP-кодов, поиск и якоря, HTML/JS/CSS-маршруты, HEAD/404/405, отображение всех модулей, копирование, восстановление поиска, клавиатура и ширины 1440/768/390/320 px. SQL-примеры выполняются в SQLite в памяти; проверяются результаты выборок и откат изменений. Node.js может вывести предупреждение об экспериментальном статусе встроенного SQLite.

## «Что проверить?»

Раздел /what-to-test содержит 17 категорий и 258 проверок: авторизация, регистрация, поиск, фильтры, сортировка, пагинация, формы, таблицы, даты и время, загрузка файлов, корзина, промокоды, checkout, оплата, профиль пользователя, email/телефон и API endpoint. У каждого пункта есть название и ожидаемый результат. Галочка означает «проверено», а не Pass; отдельные тестовые прогоны и статусы результатов не ведутся.

Выбранный сценарий хранится в якоре URL, например /what-to-test#login. Отметки сохраняются независимо для каждого сценария в localStorage текущего браузера и origin (другой порт — отдельное хранилище). Синхронизации между устройствами нет. При недоступном хранилище показывается предупреждение, отметки работают в памяти страницы. Повреждённые записи и неизвестные ID игнорируются.

«Сбросить отметки» очищает только текущий сценарий. «Отменить» восстанавливает его до следующего изменения или переключения. Копирование выдаёт название, отметки [x]/[ ] и ожидаемые результаты. Общий поиск индексирует весь текст и открывает нужный сценарий.

Материалы находятся в web/modules/what-to-test.js. Каждый сценарий — тема со стабильным id и блоком типа checklist, у которого items — массив объектов {id, title, expected, kinds}. Не меняйте ID существующих пунктов без необходимости: по ним сохраняются отметки. Новые пункты изначально не отмечены. Интерфейс — web/checklists.html и web/checklists.js. Платёжные проверки предназначены для тестового режима провайдера.

## Главная: от задачи к действию

Три крупных направления помогают выбрать следующий шаг: «Хочу разобраться» ведёт к базе знаний на /#library, «Мне нужно протестировать» — к /what-to-test, «Мне нужно решить задачу» — к /practice. Ниже расположены быстрые входы «Что проверить?», Troubleshooting, QA Toolbox и Cheat Sheets.

/practice — подборка ссылок на существующие инструкции по диагностике и шпаргалки. QA Toolbox доступен по /toolbox; все инструменты работают локально. Подборка не добавляется в число учебных разделов. Все прежние URL и сохранённые отметки остаются прежними.

Поиск расположен возле каталога; прямой вход с ?q= показывает область результатов. Главная и подборка поддерживают переход к основному содержимому, клавиатурную навигацию и видимый фокус. Используется текущая единая палитра: переключателя светлой/тёмной темы нет. Проверяются desktop/tablet/mobile, включая 1024 px.

В проекте нет отдельных lint/typecheck-конфигураций. Проверка сборки: javac --release 17 -encoding UTF-8 -d out src/Main.java; проверка синтаксиса JavaScript: node --check для каждого файла web и tests; дополнительно git diff --check и существующие тесты.

## Поиск и действия в библиотеке чек-листов

Поиск внутри /what-to-test проверяет названия категорий, пунктов и ожидания, поддерживает несколько слов и е/ё без учёта регистра. Фильтр «Категория» работает совместно с поиском. При совпадении названия категории доступны все её пункты. Результат открывает полный список с подсветкой совпадений; пустая выдача не закрывает текущий чек-лист.

«Отметить всё», «Сбросить» и копирование применяются ко всему открытому чек-листу независимо от поиска. Прогресс показывает количество, процент и полосу выполнения. Для копирования доступны Markdown (по умолчанию) и Plain text, с текущими отметками и ожиданиями. Markdown-символы в содержимом экранируются.

Локальные поиск и фильтр сохраняются в параметрах checklist-search и category, выбранный сценарий — в hash. Параметр q общего поиска остаётся независимым. Старые ID и ключи localStorage сохранены; новые пункты не отмечены.

В данных kinds — массив из positive, negative, boundary, ui-ux, technical; пункт может иметь несколько меток. Предупреждение сценария задаётся полем notice. Категории, фильтр и счётчики строятся из данных: новый сценарий добавляется в web/modules/what-to-test.js без отдельной страницы или маршрута. Сохраняйте стабильные ID и обновляйте ожидаемые количества в тестах и документации.

## Troubleshooting

/troubleshooting — библиотека из 16 пошаговых диагностик: API 400/401/403/404/409/422/500, timeout, CORS, недоступная страница, неработающая кнопка, несохранённые/неверные данные, различия local/test/stage, сбой после deploy и падение приложения. Доступна из быстрого доступа, каталога, /practice и общего поиска.

Каждый симптом раскрывает шесть частей: значение, возможные области, первую проверку, нумерованные шаги, данные для разработчика и связанные внутренние материалы. Алгоритмы проходят по относящимся к случаю границам Browser → Frontend → Network/API → Backend → Database → External services и отделяют наблюдения от гипотез. Отсутствие доступа к логам или БД фиксируется, а не заменяется предположением о причине.

Выбранный симптом хранится в hash, например /troubleshooting#api-timeout. Работают прямые ссылки, обновление и история браузера; неизвестный hash открывает первый сценарий. Параметр q общего поиска сохраняется для возврата.

Данные — web/modules/troubleshooting.js: темы со стабильными id/title и blocks. Новые типы heading (text) и ordered-list (items) переиспользуются renderer и индексом поиска. Предупреждения и содержание — текст, команды сайт не запускает. Для нового симптома достаточно добавить данные, обновить ожидаемое количество в тестах и документации; отдельный маршрут не нужен.

Семантика статусов и CORS сверена с MDN; ссылки на официальную документацию доступны в разделе. Существующие материалы и 17 категорий чек-листов сохранены.


## QA Toolbox

**/toolbox** — 15 инструментов: JSON Formatter / Validator, JSON Minify, JSON Diff, Text Diff, Base64 Encode/Decode, URL Encode/Decode, UUID Generator, Unix Timestamp ↔ Date, Character Counter, Byte Counter, JWT Decoder, Test Data Generator, Boundary Value Generator, Bug Report Builder и Test Case / Checklist Builder.

Выберите инструмент, введите данные или нажмите «Пример», затем «Выполнить». Для каждого доступны результат, копирование, очистка, описание применения и сообщения об ошибках. Выбор инструмента хранится в hash URL (например, /toolbox#jwt); содержимое полей не записывается в URL. В преобразователях оно очищается при переключении; Bug Report Builder и Test Case / Checklist Builder сохраняют локальные черновики.

Обработка выполняется в браузере без внешних библиотек и запросов с введёнными данными. **JWT не отправляется на сервер. Decoder только читает header/payload и не проверяет подпись, подлинность или срок действия токена.** Учебный пример намеренно не подписан. JWE и бинарный Base64 не поддерживаются.

Ограничения: до 100 000 символов на поле, до 400 строк для Text Diff, глубина JSON до 100 и до 2000 различий. JSON использует точность JavaScript; большие целые отклоняются, повторные ключи заменяются последним значением. JSON Diff не учитывает порядок ключей объектов, но учитывает порядок массивов. Text Diff нормализует CRLF/CR в LF. URL-кодирование рассчитано на отдельное значение параметра. Даты вводятся с явным часовым поясом, результат — UTC. Byte Counter считает UTF-8; Character Counter отдельно показывает UTF-16, code points и графемы.

Архитектура:
- web/modules/toolbox.js — конфигурация названий, описаний, полей-примеров и режимов. Поисковые темы строятся из этих данных.
- web/toolbox-core.js — чистые преобразования без DOM, сети или хранилища.
- web/toolbox.js — единый UI: поля, режим, кнопки, ошибки, результат и навигация.
- web/toolbox.html — общая страница раздела.

Чтобы добавить utility, добавьте запись в tools и обработчик её id в qaToolbox.run, затем тесты. Новая HTML-страница или копия формы не нужна. Два значения в example создают два входных поля; modes добавляет переключатель режима.

Проверки Toolbox: unit-тесты кодировок, JSON diff, времени, Unicode, UUID, JWT и ошибок; браузерные тесты всех 11 примеров, Copy/Clear, отказа Clipboard API, клавиатуры, истории, отсутствия сетевых запросов при работе JWT и ширин 320/390/768/1024/1440 px.


## Test Data Generator

Откройте **/toolbox#test-data-generator**. Инструмент включён в оглавление QA Toolbox и поиск по базе. Все операции выполняются локально; результаты не сохраняются в browser storage, URL или на сервере.

Обычная генерация: имя, email, телефон, UUID v4, целое число, строка заданной длины, дата, IPv4, URL, учебный JSON-объект и список значений выбранного типа. Настройки: количество 1–100; длина строки / поля label в JSON 0–10 000; числовой диапазон от −1 000 000 000 до 1 000 000 000; даты от 1900-01-01 до 2100-12-31 включительно. Даты не зависят от локального часового пояса. Случайные значения могут повторяться, уникальность списка не гарантируется.

**Edge Cases / Problematic Data** содержит 12 случаев: пустая строка, один/несколько пробелов, Unicode, emoji, кириллица, дефис, апостроф, длинная строка, перенос строки, HTML-like input и специальные символы. Каждый результат объясняет, что проверить. Можно выбрать отдельный случай или получить все по порядку; количество по умолчанию 12, при большем количестве цикл повторяется. Длина длинной строки: 1–10 000. HTML-like пример — буквальный текст `<b>QA example</b>`, без исполняемых конструкций.

- Generate создаёт набор; Regenerate создаёт новую случайную выборку с теми же настройками. Фиксированные edge cases повторяются намеренно.
- Copy у результата копирует исходную строку без кавычек, число либо JSON-объект. Пустая строка копируется как пустая строка, не как подпись «пусто».
- Copy all копирует JSON-массив исходных значений; пробелы, пустые строки, переносы и типы восстанавливаются через JSON.parse.
- Изменение настроек очищает устаревший результат. При запрете Clipboard API поле выделяется для ручного копирования.
- Суммарная длина генерируемых строк ограничена 100 000, сериализованных значений — 120 000 символов. Это инструмент подготовки данных для тестовых сред и проверки валидации.

Email/URL используют зарезервированный .test ([RFC 2606](https://www.rfc-editor.org/info/rfc2606/)), IPv4 — TEST-NET-1 ([RFC 5737](https://www.rfc-editor.org/info/rfc5737/)), телефоны — +1 202 555 0100–0199 из вымышленного диапазона [NANPA](https://nanpa.com/numbering/555-line-numbers). Эти значения проверяют формат, а не реальную доставку или доступность. Инструмент не звонит, не отправляет письма и не обращается к сгенерированным адресам.

web/data-generator.js содержит типы, edge cases, проверки настроек и генерацию. web/data-generator-ui.js содержит общий renderer настроек и результатов; он подключается через renderer: 'generator' в конфигурации Toolbox. Для новых типов и случаев не нужны отдельные страницы.

Тесты проверяют все типы и edge cases, диапазоны, длину, календарные границы, сохранность Copy/Copy all, Regenerate, некорректные настройки, отсутствие сетевых запросов, клавиатуру и размеры mobile/tablet/desktop.


## Boundary Value Generator

**/toolbox#boundary-value-generator** — генератор для Boundary Value Analysis, связанный с материалом **/test-design#boundaries** об анализе границ и Equivalence Partitioning. Обратная ссылка есть и в теории; инструмент доступен через поиск.

Числовой режим строит шесть точек: min − шаг, min, min + шаг, max − шаг, max, max + шаг. Шаг по умолчанию 1. Для decimal задайте шаг по требованиям, например 0.01. Поддерживаются отрицательные числа, точка и запятая как десятичный разделитель, до 30 цифр целой части и 12 дробных. Расчёт через масштабированные BigInt сохраняет точность; экспоненциальная запись не поддерживается.

Режим длины строки принимает целые minLength/maxLength от 0 до 10 000 и создаёт строки из A с шагом 1. Например, 3–50 → длины 2, 3, 4, 49, 50, 51. Максимальная создаваемая строка — 10 001 символ. ASCII A занимает одну графему, одну UTF-16 единицу и один байт UTF-8. Нулевая длина даёт пустую строку; отрицательная длина отмечается как невозможная и не попадает в Copy values.

Каждая точка показывает формулу, положение относительно соответствующей границы и принадлежность всему диапазону. Границы считаются включёнными; ожидаемое поведение нужно сверять с требованиями. При min = max или пересечении соседних точек все шесть ролей сохраняются с отметкой о совпадении. При узком диапазоне min + шаг может оказаться выше max — класс определяется фактическим значением.

Generate строит точки. Copy values копирует числа по одному на строку, а в режиме длины — JSON-массив настоящих строк, сохраняющий пустые значения. Copy as checklist создаёт Markdown с шестью пояснёнными точками; невозможные отрицательные длины помечаются как пропущенные. При недоступном Clipboard API экспорт выделяется для ручного копирования. Изменение настроек убирает устаревший результат; отсутствующие границы, min > max, некорректные числа, дробные/отрицательные длины и неположительный шаг показывают ошибку.

web/boundary-generator.js — вычисления и экспорт; web/boundary-generator-ui.js — UI на общем каркасе Toolbox. Все операции локальны, без сети и сохранения ввода. Тесты охватывают decimal, совпадения, нулевую длину, ограничения, копирование, ссылки на теорию, клавиатуру и адаптивность.


## HTTP Status Code Finder

**/http-codes** — интерактивный справочник 26 основных статусов (включая 410 Gone). Поиск принимает код, английское название и русское описание проблемы: 409, «нет авторизации», «ресурс не найден», «нет прав», «ошибка валидации». Используются слова и заданные синонимы, без внешнего AI или запросов на сервер. Число из трёх цифр ищется как точный код.

Фильтры «Все», 1xx–5xx работают совместно с поиском. В каждой карточке есть код, название, объяснение; раскрываемый блок содержит пример, проверки QA, похожие статусы, отличие и ссылку на материал /http. Раздел «Часто путают» ведёт к подробным сравнениям 200/201/204, 400/422, 401/403, 404/410, 409/422 и 500/502/503/504. Сравнения остаются доступны при фильтрации карточек.

Старые адреса /http-codes#codes-1xx … #codes-5xx сохранены. Прямая ссылка на карточку: /http-codes#status-409; на сравнение: /http-codes#compare-409-422. Карточка по прямой ссылке раскрывается автоматически. Поиск и класс хранятся в status-search и status-class; общий параметр q для возврата в поиск базы сохраняется. Если фильтр скрывает цель прямой ссылки, Finder сбрасывает этот фильтр и показывает цель. Поддерживаются обновление страницы, назад/вперёд и клавиатура.

Базовые названия/объяснения — web/data.js; расширенные данные, синонимы, сравнения и чистая функция поиска — web/modules/http-codes.js; интерфейс — web/http-finder.js. Общий поиск индексирует карточки и сравнения. Новый статус добавляется в httpGroups и details, без отдельной страницы. Страница использует существующие стили и адаптивный каркас.

Семантика сверена с [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-status-codes) и [RFC 6585 для 429](https://www.rfc-editor.org/rfc/rfc6585.html#section-4). Примеры и проверки — учебные сценарии: ответ необходимо сопоставлять с контрактом и логами, статус не доказывает первопричину. 401 не равен 403, клиентский timeout без ответа не равен 504, а все удалённые ресурсы не обязаны возвращать 410.

Тесты проверяют полноту карточек, похожие коды, ссылки, поиск по проблемам, пересечение фильтров, сравнения, сохранение URL, клавиатуру и размеры 320/390/768/1024/1440 px.


## Bug Report Builder

**/toolbox#bug-report-builder** — конструктор отчёта с Title, Environment, Preconditions, Steps to reproduce, Actual result, Expected result, Severity, Priority и Additional information. Подсказки находятся рядом с полями; для Title приведены плохой и хороший примеры. Ссылка ведёт в существующий раздел /bug-reports.

Шаги добавляются и удаляются динамически; кнопки «Выше»/«Ниже» меняют порядок, «Вернуть удалённый шаг» восстанавливает последнее удаление. Фокус остаётся на редактируемом шаге. Пустые шаги сохраняются в черновике, но не входят в экспорт; непустые нумеруются последовательно.

Экспорт обновляется сразу: Plain text, Markdown или Jira-friendly (wiki markup: h2. и #). Разметка внутри введённого текста экранируется для выбранного формата. Jira-friendly предназначен для редактора с поддержкой wiki markup, а не для автоматической отправки в Jira; в других редакторах используйте Plain text/Markdown. Copy копирует текущий формат; при отказе Clipboard API текст выделяется для ручного копирования.

Проверка по правилам не блокирует работу: предупреждения об отсутствии Actual result, Expected result, Environment, содержательных шагов и слишком абстрактном Title. Title проверяется по длине и небольшому набору общих формулировок; это эвристика, не семантическая оценка. Отсутствие замечаний не гарантирует качество отчёта. Severity и Priority выбираются отдельно и автоматически не назначаются.

Черновик всех полей, порядка шагов и формата синхронно сохраняется после изменений в localStorage под ключом qaHelpers.bugReport.v1. Он восстанавливается после обновления и переключения инструментов. Данные локальны для браузерного профиля и origin (hostname + порт), не отправляются на сервер. Очистка данных сайта удалит черновик. При запрете/переполнении хранилища отображается предупреждение; остаётся копия в памяти вкладки, которая не переживёт обновление. Повреждённая запись не перезаписывается до нового ввода, пользователь получает сообщение.

web/bug-report.js — схема, правила и экспорт; web/bug-report-ui.js — форма, управление шагами, сохранение и восстановление. Конфигурация Toolbox использует renderer: 'bug-report'. Тесты проверяют правила, три формата, порядок шагов, копирование, reload, повреждённое/недоступное хранилище и адаптивность.

## Помощник выбора техники тест-дизайна

**/test-design#technique-advisor** — пять вопросов о входных ограничениях, комбинациях параметров, условиях, состояниях и бизнес-процессе. Ответы «Да», «Нет», «Пока не знаю» приводят к набору совместимых рекомендаций: Boundary Value Analysis, Equivalence Partitioning, Pairwise, Decision Table, State Transition и сценарный подход. У каждой есть причины выбора, пример, порядок применения, типичные ошибки и ссылка на тему qaHelp. Вход доступен также из /practice.

«Назад» и «Изменить ответы» сохраняют выбор в текущей странице; «Начать заново» очищает его. После обновления страницы опрос начинается заново. Неизвестные ответы не считаются подтверждёнными признаками; без совпадений помощник предлагает уточнить требования. Данные обрабатываются локально в браузере.

Конфигурация и чистая функция `recommend(answers)` находятся в `web/test-design-advisor.js`, DOM-интерфейс — в `web/test-design-advisor-ui.js`. Для расширения добавьте вопрос в `questions`, описание техники в `techniques` и правило в `rules` (`question`, `recommends`, `reason`). Правила срабатывают на `yes`, результаты объединяются без дубликатов, причины сохраняются. Новый вопрос автоматически появляется в интерфейсе; обновите текст о числе вопросов при изменении их количества. Тесты: `tests/test-design-advisor.test.cjs` и сценарий в `tests/browser.cjs`.

## Test Case / Checklist Builder

**/toolbox#test-case-builder** — Test Case (ID, Title, Preconditions, Test Data, Steps, Expected Result, Priority) и Checklist (Title, список проверок). Ссылка «Test Case vs Checklist» ведёт на /test-cases#formats.

Шаги и проверки можно добавлять, перемещать, дублировать и удалять. Каждый режим сохраняет свой документ. Пустые пункты остаются в черновике, но пропускаются в экспорте. Copy и скачивание поддерживают Markdown, Plain text и CSV. CSV: одна строка на шаг/проверку, поля документа повторяются; кавычки и переносы экранируются, потенциальные формулы получают защитный апостроф. Скачиваемый CSV содержит UTF-8 BOM.

Оба документа, режим и формат сохраняются локально в qaHelpers.testCase.v1, без отправки на сервер. Черновик привязан к браузеру и origin. При недоступном хранилище данные остаются в памяти вкладки до обновления; интерфейс сообщает об этом. Повреждённая запись не заменяется до нового ввода. При отказе Copy текст выделяется для ручного копирования. Логика: web/test-case.js; интерфейс: web/test-case-ui.js.
